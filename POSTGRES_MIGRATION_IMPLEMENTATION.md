# PostgreSQL / Supabase implementation status

## Implemented on `supabase-postgres-migration`

- FastAPI selects PostgreSQL when `DATABASE_URL` is configured; production fails closed if it is missing. SQLite remains available for local development.
- PostgreSQL access runs through `app/db.py`, using pooled transactions, `SET LOCAL ROLE sultan_app`, and transaction-local actor/branch/login settings.
- Startup checks required public tables/columns, RLS enablement and policies, and verifies that `sultan_app` is NOLOGIN, NOSUPERUSER and NOBYPASSRLS.
- Empty-database bootstrap creates the first owner only when `users` is empty and a strong `SULTAN_INITIAL_ADMIN_PASSWORD` is supplied. It does not overwrite existing users.
- Route integration tests exercise login, branch isolation, products, sales, expenses, debts/payments, repairs, purchases, returns, transfers, cash closing, reports, exports, stocktake, notifications and zakat against PostgreSQL 17 in CI.
- PostgreSQL mode disables SQLite file backup/restore endpoints; database backups and restores must be managed through Supabase/operator procedures.
- Render Blueprint is configured as a Docker Web Service with no Render database and no persistent disk. It requires server-side `DATABASE_URL` and `SULTAN_INITIAL_ADMIN_PASSWORD`; the secret key is generated by Render.

- Historical `sale_items.unit_cost` values absent from an old SQLite source are estimated from current product purchase prices by the migration script; review that limitation before migrating historical financial data.

## Required Render environment

- `APP_ENV=production`
- `DATABASE_URL`: Supabase Shared Pooler transaction-mode connection string (port 6543), stored only as a Render secret.
- `SULTAN_SECRET_KEY`: unique random secret of at least 32 characters (Render Blueprint generates it).
- `SULTAN_INITIAL_ADMIN_PASSWORD`: strong first-owner password, supplied as a secret.
- `SULTAN_COOKIE_SECURE=1`

Do not add a Render Postgres database or persistent disk. Do not point the application at SQLite in production. Do not merge/deploy to production on the basis of CI alone; complete the live smoke tests first.
