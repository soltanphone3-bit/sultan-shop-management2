# SULTAN SHOP MANAGEMENT

مشروع إدارة متجر Full-Stack باستخدام FastAPI + HTML/CSS/JavaScript؛ SQLite للتطوير المحلي وPostgreSQL/Supabase لوضع الإنتاج.

## التشغيل محلياً
1. ثبّت Python 3.11 أو أحدث.
2. افتح الطرفية داخل مجلد المشروع.
3. أنشئ بيئة افتراضية وثبّت المتطلبات:
   ```bash
   python -m venv .venv
   # Windows: .venv\\Scripts\\activate
   # macOS/Linux: source .venv/bin/activate
   pip install -r requirements.txt
   ```
4. شغّل `uvicorn app.main:app --reload` ثم افتح `http://127.0.0.1:8000`.

## الدخول الأول
- المستخدم: `admin`
- كلمة المرور المؤقتة: `ChangeMe123!`

غيّر كلمة المرور فور أول دخول. في وضع التطوير المحلي، بيانات الدخول الأولية هي `admin` / `ChangeMe123!`. في وضع الإنتاج `APP_ENV=production` يرفض التطبيق البدء ما لم تضبط `SULTAN_SECRET_KEY` فريدة بطول 32 حرفاً على الأقل و`SULTAN_INITIAL_ADMIN_PASSWORD` بطول 12 حرفاً على الأقل. تُستخدم كلمة المرور الأخيرة فقط عند إنشاء قاعدة بيانات جديدة بلا مستخدمين؛ لا تغيّر كلمة مرور قاعدة بيانات موجودة. فعّل `SULTAN_COOKIE_SECURE=1` واستخدم HTTPS دائماً.

- يجب أن يختبر مالك النظام صلاحيات كل موظف عملياً بحساب مستقل قبل تشغيل المتجر.
- لا يوجد نشر عام أو قاعدة بيانات إنتاجية أو مزود استضافة مربوط بهذا التسليم.

## قاعدة البيانات
في التشغيل المحلي دون `DATABASE_URL` ينشئ التطبيق `sultan.db` تلقائياً. في الإنتاج عند ضبط `DATABASE_URL` يتصل التطبيق بقاعدة PostgreSQL الموجودة على Supabase ولا ينشئ ملف SQLite. احتفظ بنسخة خارجية من SQLite محلياً، واستخدم نسخ Supabase الاحتياطية لقاعدة الإنتاج.


## تحديث الأمان والصلاحيات
- أضيفت صلاحيات موظفين محفوظة في قاعدة البيانات وتُفحص في الخادم عند كل طلب API.

- يمكن للمالك تنزيل نسخة احتياطية متسقة باستخدام آلية SQLite online backup، واستعادة ملف قاعدة البيانات من صفحة الإدارة. قبل الاستبدال يحتفظ التطبيق بنسخة أمان على الخادم، ويفحص سلامة الملف، ثم يبطل الجلسات بعد الاستعادة.

## قبل النشر العام
اضبط `SULTAN_SECRET_KEY` على قيمة عشوائية طويلة وفريدة، واضبط `SULTAN_COOKIE_SECURE=1` عند استخدام HTTPS. استخدم HTTPS دائماً، واحتفظ بنسخ احتياطية خارج خادم التطبيق. هذه التعديلات لا تغني عن اختبار اختراق ومراجعة أمنية مستقلة قبل تشغيل المتجر فعلياً.

## تشغيل تجريبي بالحاويات
1. انسخ `.env.example` إلى `.env` وأنشئ قيمتين سريتين قويتين وفريدتين لـ `SULTAN_SECRET_KEY` و`SULTAN_INITIAL_ADMIN_PASSWORD`. لا تشارك ملف `.env`.
2. شغّل `docker compose up --build -d`.
3. افحص `http://127.0.0.1:8000/healthz`؛ ينبغي أن يعيد `status: ok`.
4. اربط Reverse Proxy موثوقاً يوفر HTTPS قبل إتاحة التطبيق للإنترنت، ولا تفتح المنفذ 8000 مباشرة للعامة.
5. احتفظ بنسخ احتياطية خارج الخادم واختبر الاستعادة على نسخة منفصلة.


## النشر على Render
1. استخدم فرع `supabase-postgres-migration` وملف `render.yaml` لإنشاء خدمة مستقلة باسم `sultan-shop-management2`؛ لا تربط الخدمة القديمة الخاصة بالموقع الثابت بهذا التطبيق.
2. إعداد Blueprint يطلب قيمتين سريتين من لوحة Render: `DATABASE_URL` (رابط اتصال PostgreSQL الخاص بمشروع Supabase الصحيح) و`SULTAN_INITIAL_ADMIN_PASSWORD` (كلمة مرور أولية قوية لا تقل عن 12 حرفاً).
3. اترك `SULTAN_SECRET_KEY` على القيمة العشوائية التي ينشئها Render، ولا تشارك أي سر أو تضعه في Git.
4. لا يحتاج هذا النشر إلى قرص Render دائم؛ قاعدة البيانات خارجية على Supabase. لا تستخدم رابط المشروع أو مفتاح anon بدلاً من رابط اتصال PostgreSQL.
5. بعد ضبط الأسرار ونجاح النشر، افحص `/healthz)، ثم سجّل الدخول باسم `admin` وغيّر كلمة المرور فوراً.
6. راجع خطة الاستضافة؛ الإعداد الحالي Free لتجنب أي تكلفة تلقائية، وقد يدخل في السكون. التشغيل التجاري المستمر يحتاج خطة مناسبة بعد مراجعة السعر.

**مهم:** لا تعتبر الخدمة جاهزة للإنتاج قبل التحقق من نجاح CI، وفحص الصحة، واختبار تسجيل الدخول والمبيعات والمخزون والتقارير على بيئة PostgreSQL معزولة، ثم تفعيل النسخ الاحتياطية في Supabase.


## مسار PostgreSQL الإنتاجي (قيد التحقق)

- التشغيل المحلي دون `DATABASE_URL` يستخدم SQLite كما كان سابقاً.
- عند ضبط `DATABASE_URL` ينتقل التطبيق إلى PostgreSQL عبر psycopg pool، وتُنفّذ كل معاملة بدور `sultan_app` مع سياق RLS محلي للمعاملة. لا يسمح مسار الاتصال بأي استعلام دون سياق مستخدم/فرع أو سياق تسجيل الدخول.
- يجب أن يكون الدور `sultan_app` موجوداً بصلاحيات `NOLOGIN` و`NOSUPERUSER` و`NOBYPASSRLS`، وأن يكون مستخدم اتصال التطبيق مخولاً بتنفيذ `SET ROLE sultan_app`.
- يفحص التطبيق عند بدء التشغيل الجداول والأعمدة المطلوبة، وتفعيل RLS على جميع جداول التطبيق، ووجود سياسات موجهة إلى `sultan_app`. لا ينشئ مخطط Supabase تلقائياً ولا يغيّر قاعدة البيانات الحية.
- عند أول تشغيل على قاعدة PostgreSQL فارغة، ينشئ التطبيق فرعاً رئيسياً وحساب المالك `admin` باستخدام `SULTAN_INITIAL_ADMIN_PASSWORD`. يجب إدخال كلمة مرور قوية من 12 حرفاً على الأقل في إعدادات الاستضافة؛ لا تُرسل كلمة المرور أو رابط قاعدة البيانات في المحادثة.
- نقاط نسخ/استعادة SQLite لا تعمل في وضع PostgreSQL. تُدار نسخ PostgreSQL عبر Supabase/أدوات النسخ الإدارية خارج واجهة الويب، ولا تُرفع ملفات قاعدة البيانات إلى التطبيق.
- إعداد Render الحالي يعرّف خدمة منفصلة باسم `sultan-shop-management2` في Frankfurt ويطلب `DATABASE_URL` و`SULTAN_INITIAL_ADMIN_PASSWORD` كقيم سرية من لوحة Render. لم يتم ربط أسرار قاعدة البيانات أو تنفيذ نشر إنتاجي حتى الآن.
- خطة Render في الملف مضبوطة على Free لتجنب إنشاء تكلفة مدفوعة تلقائياً؛ هذه الخطة قد تدخل في السكون وليست اختياراً مثالياً لتشغيل متجر مستمر. يجب ترقية الخطة بعد مراجعة السعر عند اعتماد التشغيل التجاري.

**تنبيه تشغيل:** هذا المسار قيد التحقق باختبارات CI وتوافق الاستعلامات مع مخطط Supabase الحالي. لا تعتبره نسخة إنتاجية معتمدة حتى ينجح CI، ويُختبر تسجيل الدخول والمبيعات والمخزون والتقارير على بيئة PostgreSQL معزولة، ثم يتم التحقق من نشر Render وفحص الصحة.

## نقل بيانات SQLite الموجودة (اختياري)
إذا كانت لديك قاعدة SQLite قديمة خارج المستودع، أضفها إلى جهازك محلياً ولا ترفعها إلى Git. أداة `scripts/migrate_sqlite_to_postgres.py` تعمل بوضع المعاينة افتراضياً، وتتحقق من المفاتيح الخارجية ومطابقة الأعمدة، وترفض الكتابة إذا لم تكن جداول PostgreSQL فارغة.

1. خذ نسخة احتياطية مستقلة من ملف SQLite.
2. ثبّت المتطلبات، ثم اضبط `SQLITE_DB_PATH` على ملف المصدر و`MIGRATION_DATABASE_URL` على اتصال إداري خاص بمشروع Supabase. لا تضبط `DATABASE_URL` أثناء الترحيل.
3. شغّل `python scripts/migrate_sqlite_to_postgres.py` لمعاينة أعداد الصفوف دون كتابة.
4. بعد مراجعة المعاينة، نفّذ على مسؤوليتك من الطرفية المحلية فقط: `CONFIRM_SQLITE_MIGRATION=YES python scripts/migrate_sqlite_to_postgres.py`.
5. تتحقق الأداة من أعداد الصفوف بعد النقل وتعيد ضبط identity sequences. إذا كان ملف SQLite قديماً ولا يحتوي `sale_items.unit_cost`، تستخدم الأداة سعر الشراء الحالي للمنتج كتقدير تاريخي وتُظهر ذلك في رسالة النجاح؛ يجب مراجعة هذا التقدير محاسبياً.

لا تشغّل الأداة على قاعدة إنتاج تحتوي بيانات؛ فهي ترفض أي جدول هدف غير فارغ. لا ترسل رابط الاتصال الإداري أو ملف قاعدة البيانات إلى المحادثة أو إلى Git.
